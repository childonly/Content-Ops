项目概览

Content Ops Hub 是一个内容运营一体化平台，将三个独立项目合并为统一的工程体系。

i
合并背景：Content Ops Hub 整合了 xhs-auto-pipeline（小红书自动化管线）、social-radar（社交情报雷达）、content-ops-hub（内容运营核心）三个项目，消除了重复代码，统一了数据层与技能调用接口，形成从情报采集、趋势发现、内容生产到发布运营的完整闭环。

xhs-auto-pipeline / social-radar / content-ops-hub

xhs-auto-pipeline

小红书内容自动化管线，涵盖内容生成、图片生成、发布队列等核心能力。已整合为内容工作室、图片工作室、发布队列模块。

social-radar

社交情报雷达系统，实时监控社交平台趋势与竞品动态。已整合为情报中心、趋势发现、数据分析模块。

content-ops-hub

内容运营核心框架，提供流水线编排、闭环管理与统一技能调度。作为平台基座承载所有业务模块。

05

运营流水线 (Pipeline)

6 阶段闭环流水线，从趋势发现到迭代优化，实现内容运营全自动化。

Pipeline 6 阶段流程图

STAGE 1

趋势发现

TREND_DISCOVERY

通过多平台热点扫描与社交情报雷达，发现当前热门趋势与潜在爆款话题，为内容创作提供方向指引。

STAGE 2

标签研究

HASHTAG_RESEARCH

基于发现的趋势，研究相关话题标签的热度、竞争度与关联性，筛选出最优标签组合策略。

STAGE 3

内容生成

CONTENT_GENERATION

调用内容工作室、图片工作室、视频工作室，基于趋势与标签自动生成图文、图片与视频内容。

STAGE 4

内容发布

PUBLISHING

将生成的内容加入发布队列，通过双引擎并行架构执行定时发布，支持小红书等多平台分发。

STAGE 5

效果追踪

PERFORMANCE_TRACKING

追踪已发布内容的数据表现，包括阅读量、互动率、粉丝增长等核心指标，形成效果数据面板。

STAGE 6

迭代优化

ITERATION

基于效果数据分析，优化下一轮趋势发现与内容策略，形成持续改进的运营闭环。

# 方法 路由路径 功能描述 对应模块

05 GET /api/hashtags/research 获取标签研究数据 标签研究
06 POST /api/content/generate 生成内容（图文/脚本/文案） 内容工作室
07 POST /api/images/generate 多引擎图片生成 图片工作室
08 POST /api/videos/generate 视频内容生成 视频工作室
09 GET /api/publish/queue 获取发布队列列表 发布队列
10 POST /api/publish/execute 执行发布任务 发布队列
11 GET /api/analytics/creators 获取创作者分析数据 数据分析
12 GET /api/analytics/competitors 获取竞品分析报告 数据分析
13 GET /api/pipeline/status 获取流水线运行状态 闭环管理
14 POST /api/pipeline/trigger 触发流水线执行 闭环管理

数据库表结构 (11 Tables)

SQLite 数据库采用 WAL 模式，共 11 张业务表，通过 better-sqlite3 同步驱动访问。

# 表名 中文名称 功能说明 关联模块
01 trends 趋势数据表 存储多平台趋势热点数据，含热度值、来源平台、发现时间 趋势发现
02 radar_feeds 情报流表 存储社交情报雷达采集的信息流，含来源、内容摘要、情感标签 情报中心
03 hashtags 标签表 存储话题标签研究数据，含热度、竞争度、关联标签 标签研究
04 contents 内容表 存储 AI 生成的内容，含图文、脚本、文案等多类型内容 内容工作室
05 images 图片表 存储多引擎生成的图片记录，含引擎类型、文件路径、提示词 图片工作室
06 videos 视频表 存储视频生成与转录记录，含脚本、成片路径、字幕数据 视频工作室
07 publish_tasks 发布任务表 存储发布队列任务，含目标平台、计划时间、发布状态 发布队列
08 publish_logs 发布日志表 存储发布执行日志，含成功/失败记录、错误信息、时间戳 发布队列
09 analytics_records 分析记录表 存储创作者与竞品分析数据，含粉丝数、互动率、增长趋势 数据分析
10 pipeline_runs 流水线运行表 存储流水线执行记录，含 6 阶段状态、开始/结束时间、结果 闭环管理
11 skill_configs 技能配置表 存储技能配置信息，含技能类型、参数、LLM 模型绑定 全局
i
WAL 模式：Write-Ahead Logging 模式允许多个读操作与一个写操作并发执行，显著提升数据库读写性能，适合内容运营平台高频读写场景。

部署指南

支持开发模式与生产模式部署，推荐使用 PM2 进行进程管理。

1

环境准备

确保已安装 Node.js 18+、npm/pnpm 包管理器。克隆项目代码并安装依赖。

# 安装后端依赖 cd backend && npm install # 安装前端依赖 cd ../frontend && npm install
2

开发模式启动 (一键脚本)

使用项目根目录下的 start-all-services.ps1 脚本同时启动前后端服务。

# PowerShell 一键启动所有服务 .\start-all-services.ps1 # 后端启动于 http://localhost:3100 # 前端启动于 http://localhost:5180
3

生产模式部署 (PM2)

使用 PM2 进程管理器进行生产部署，支持自动重启、日志管理与负载监控。

# 安装 PM2 全局 npm install -g pm2 # 构建前端 cd frontend && npm run build # 构建后端 cd ../backend && npm run build # PM2 启动后端服务 pm2 start dist/index.js --name "content-ops-api" # PM2 启动前端静态服务 (可选) pm2 serve ../frontend/dist 5180 --name "content-ops-web" # 保存 PM2 配置 pm2 save
4

端口配置

后端 API 服务运行在端口 3100，前端开发服务器运行在端口 5180。确保端口未被占用。

# 后端端口: 3100 (Express API) # 前端端口: 5180 (Vite Dev Server) # API 前缀: /api/ # 前端代理: Vite proxy -> http://localhost:3100
5

健康检查与监控

启动后通过 PM2 监控面板查看服务运行状态，确保前后端服务正常运行。

# 查看进程状态 pm2 status # 查看实时日志 pm2 logs # 打开监控面板 pm2 monit # 验证后端 API curl http://localhost:3100/api/pipeline/status

技能类型 (Skill Types)

平台技能系统分为三种类型，以颜色区分，支持灵活组合与调度。

F
file
基于文件脚本的技能，通过本地脚本文件执行任务。无外部依赖，运行速度快，适合内容生成、脚本撰写等本地处理场景。
xhs-content script-writer humanizer-zh
A
api
基于外部 API 调用的技能，通过 HTTP 请求对接第三方服务。支持多平台数据采集与云端 AI 能力调用。
trend-research douyin creator-analytics
L
local-model
基于本地 AI 模型的技能，通过 Ollama 等本地推理引擎运行。数据隐私安全，无 API 费用，适合图片生成与模型推理。
CogView SDXL Local Engine
i
技能调度：流水线编排引擎根据任务需求自动选择合适的技能类型。file 类型优先执行（低延迟），api 类型用于外部数据获取，local-model 类型用于需要隐私保护的 AI 推理任务。三种类型可自由组合，支持同一模块内混合调用。
10

LLM 配置

支持四种 LLM 部署模式，满足不同场景下的成本、性能与隐私需求。

LOCAL 本地模型
基于 Ollama 运行本地大语言模型，数据完全不出本机，零 API 费用。适合对数据隐私要求高的场景及离线环境。

支持模型：Llama 3、Qwen、ChatGLM 等开源模型
适用场景：内容生成、文案润色、本地推理
CLOUD 云端模型
对接 GLM（智谱 AI）与 DeepSeek 云端 API，提供高质量推理能力，按量计费。适合需要强推理能力的复杂任务。

支持模型：GLM-4、DeepSeek-V3、DeepSeek-R1
适用场景：深度分析、脚本创作、趋势预测
HYBRID 混合模式
本地 + 云端智能调度，根据任务复杂度自动选择最优模型。简单任务走本地（低成本），复杂任务走云端（高质量），兼顾性能与成本。

调度策略：任务分级路由 / 负载均衡 / 故障自动切换
适用场景：全流水线运行、大规模内容生产
CUSTOM 自定义模型
支持用户自定义配置 LLM 模型端点，可接入私有部署模型或第三方兼容 OpenAI 接口的服务，灵活适配各类推理后端。

配置方式：skill_configs 表存储模型绑定 / 自定义 API Base URL
适用场景：企业私有化部署、自定义模型接入
