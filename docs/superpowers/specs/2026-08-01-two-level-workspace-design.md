# 两层工作台与真实节点执行设计

日期：2026-08-01  
状态：用户已确认按推荐方案直接实施

## 1. 目标

工作台分为两个互相独立但可衔接的层级：

1. **业务编排流程**：定义可复用的流程蓝图，回答“需要哪些模块、先后顺序是什么”。继续使用 `business_flows` 保存节点和连线。
2. **项目节点工作流**：从一个业务编排蓝图创建项目执行实例，回答“这一次实际输入了什么、每一步产生了什么、如何微调、最终交付物在哪里”。

第二层默认采用半自动逐步模式：执行一个节点后立即显示输入、输出、来源、模型、耗时和错误；用户可修改提示词或参数后重试，也可确认结果并进入下一步。额外提供“一键连续执行”，遇到人工节点、缺少配置或失败时暂停。

## 2. 方案比较

### 方案 A：直接给 `business_flows` 增加运行状态

实现较快，但会把流程模板和某次运行结果混在一起，重复执行、版本回溯和多个项目并行会互相覆盖，不采用。

### 方案 B：双层模型 + 节点适配器（采用）

`business_flows` 只保存蓝图；新增项目实例和项目节点表保存快照、执行状态与结果。节点适配器复用现有趋势、标签、内容、图片、审核、发布和分析服务。边界清晰，可逐步把模拟节点替换为真实节点。

### 方案 C：独立事件驱动工作流引擎

扩展性最强，但会引入队列、事件总线和分布式任务管理，当前项目规模不需要，暂不采用。

## 3. 页面架构

`/workspace` 顶部提供两个层级切换：

- **业务编排**：最近编排、新建编排、删除编排、编排画布、右键推荐下一节点并自动连线。
- **项目工作流**：最近项目、新建项目；新建时选择一个业务编排蓝图并填写项目名称、初始关键词/素材。

项目工作流页面采用四区布局：

- 左侧：项目列表、蓝图信息、整体进度。
- 中央：项目节点画布；节点直接显示状态和结果摘要。
- 右侧：节点检查器；包含输入、结果预览、提示词/参数、来源、模型、耗时、错误与重试。
- 底部：运行时间线和“待发布成果”区域。

## 4. 数据模型

新增表只做追加式迁移：

### `project_workflows`

- `id`, `flow_id`, `name`, `description`
- `status`: `draft | running | waiting_review | ready_to_publish | completed | failed`
- `mode`: `step | continuous`
- `initial_input`: JSON
- `nodes_snapshot`, `edges_snapshot`: 创建时冻结蓝图版本
- `current_node_id`, `final_content_id`
- `created_at`, `updated_at`, `completed_at`

### `project_workflow_nodes`

- `workflow_id`, `node_id`, `node_type`, `module_id`, `label`, `position`
- `status`: `pending | running | waiting_review | completed | failed | skipped | blocked`
- `prompt`, `config`, `input_snapshot`, `output_snapshot`
- `output_type`, `artifact_refs`, `source_refs`
- `provider`, `model`, `error`, `attempt`
- `started_at`, `completed_at`, `duration_ms`

节点输出只保存本节点直接输入的引用和直接结果，不再递归嵌套全部历史上下文。

## 5. 节点适配器

服务端增加统一适配器接口：

```ts
interface ProjectNodeAdapter {
  canExecute(context): AvailabilityResult
  execute(context): Promise<NodeArtifact>
}
```

首批真实适配器：

- `radar` / `trends`：读取或调用真实 TikHub 趋势服务，保留来源、采集时间和原始指标。
- `hashtags`：调用真实标签研究；无真实指标时标记为 `estimated`，不得伪装成实时热度。
- `content`：调用现有内容生成服务，保存 `contentId`、标题、正文、标签及实际 LLM。
- `image-studio` / 内容配图：调用默认图片引擎，保存图片路径和实际引擎。
- `draft-review`：人工节点，进入 `waiting_review`，不自动通过。
- `publish`：生成待发布成果并进入 `ready_to_publish`；默认不自动向外发布。
- `analytics`：仅在存在真实发布记录时执行，否则显示前置条件不足。

尚未接入的模块返回 `blocked` 和明确原因，不能标记为成功或模拟完成。

## 6. 推荐下一节点

候选来自“能力目录”，根据当前模块、已存在节点、连接关系和配置可用性计算。菜单分为：

- 推荐下一步：1–3 个最高优先级候选。
- 更多可选模块：其余合法后继。
- 不可用项：可展示但禁用，并说明缺少登录、API Key、输入或引擎。

选择候选后，在当前节点右侧创建节点并自动添加有向连线；若节点已存在，则只创建合法连线并定位该节点。

## 7. 引擎与配置

- 图片默认模型改为 `cogview-3-flash`，名称和说明同步更新。
- 引擎中心按“可用、需配置、未安装”区分，不允许把不可用引擎设置为默认。
- 当前未安装的 RedInk、guizang-card、Auto-Redbook、baoyu、xhs-ops 不伪造为已配置；页面展示所需环境变量、检测结果和配置入口。
- LLM 增加顶部快速选择，候选仅包含已启用且健康检查通过的提供商；保留按节点覆盖模型。

## 8. 数据真实性

- 所有趋势、标签和分析结果增加 `sourceType: observed | estimated | simulated`。
- `observed` 必须包含平台、采集时间和可用的来源 URL/原始 ID。
- 随机增长率、构造标签和模板数据只能标记为 `estimated` 或 `simulated`。
- 情报中心统一前后端响应契约，趋势列表扁平化后再渲染；详情面板显示原始指标与来源。

## 9. 删除与安全

- 删除业务编排前二次确认；数据库级联删除其历史运行记录。
- 若编排已被项目工作流引用，默认禁止删除并列出引用数量；用户应先归档或删除对应项目。
- 项目工作流删除需要二次确认，只删除实例和节点结果，不删除生成的业务内容；内容仍可在内容工作室管理。
- 发布始终是显式动作；自动连续执行在发布节点前暂停。

## 10. 验收标准

- 最近项目/编排可删除，成功后列表、选中状态和 URL 同步更新。
- 右键节点可看到与功能相关的候选，选择后生成节点和连线。
- 从蓝图创建项目后，每个节点可单独执行、查看结果、修改提示词并重试。
- 运行结果不再出现 `undefined`，不再递归嵌套完整历史结果。
- 最终内容集中进入待发布区，并且不会未经确认自动发布。
- CogView-3-Flash 成为可用默认图片模型；不可用引擎无法被误设为默认。
- 情报、趋势和标签结果显示数据来源与真实性标识，可打开详情。
- 自动化列表支持详情、编辑、单删和批量删除。
- 服务端测试、前端构建、深浅模式和核心流程回归通过。
