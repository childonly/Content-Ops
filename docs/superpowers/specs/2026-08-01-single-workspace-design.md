# 方案 C：单一工作台入口设计说明

日期：2026-08-01  
状态：已按用户确认实施第一阶段

## 1. 目标与边界

方案 C 将“最近项目 + 新建项目”作为系统默认入口。用户先选择一个内容项目，再进入该项目的编排画布；原有仪表盘、趋势发现、内容工作室、流水线和系统管理页面继续保留，作为高级入口或兼容入口。

本阶段只调整入口和工作区容器，不改变已有业务流程的 API、路由语义、节点数据结构、执行逻辑或权限边界。项目直接复用现有 `business_flows` 数据，不新建平行的项目表，避免迁移已有编排数据。

## 2. 用户路径

```text
默认入口 /workspace
    ├─ 选择最近项目
    │      └─ 加载项目节点与连线 → 进入编排画布
    └─ 新建项目
           └─ 创建空白 business flow → 自动进入编排画布

画布内：添加模块/技能 → 连线 → 执行 → 底部运行时间线查看最近运行
旧入口：/dashboard、/content、/radar、/pipeline、/admin 等继续可用
```

## 3. 页面组成

`WorkspaceView.vue` 负责工作区编排，不复制 FlowHome 的节点业务逻辑：

- 左侧“最近项目”：展示项目名称、状态、节点数和运行次数；支持新建与切换。
- 中央画布：复用 `FlowHome`，通过 `initial-flow-id` 加载所选项目，保证原有拖拽、连线、执行和模型配置能力不回归。
- 右侧项目检查器：显示当前项目概况、节点/连线/运行统计，并提供进入业务流管理的入口。
- 底部运行时间线：读取已有运行记录 API，展示最近运行状态、开始时间和步骤数。

项目切换使用 URL 查询参数 `?project=<id>`，因此可以刷新、复制链接并恢复当前项目。创建项目后自动选中并进入画布。

## 4. 数据与错误处理

- 项目列表：`businessFlowApi.getList({ page: 1, pageSize: 100 })`。
- 新建项目：`businessFlowApi.create({ name, description, nodes: [], edges: [] })`。
- 运行时间线：`businessFlowApi.getRuns(flowId, 8)`。
- 列表加载失败时保留空状态并提示错误；运行记录失败时不阻塞画布加载。
- 没有项目时显示明确的新建引导；创建名称为空时阻止提交。
- 历史页面仍由原路由渲染，工作台失败不会影响旧页面。

## 5. 兼容性与后续演进

第一阶段采用“工作台壳层 + 既有编排画布”的渐进式方案，优先降低迁移风险。下一阶段可在不改数据结构的前提下，把 FlowHome 的模块库、画布工具栏和节点检查器拆成可复用区域，进一步收敛为真正的四区单画布布局；该拆分不属于本次入口切换的必需条件。
