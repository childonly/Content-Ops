# 项目节点工作台与画布成果展示设计

日期：2026-08-02  
状态：交互方案已由用户确认，等待书面规格复核

## 1. 背景与目标

现有项目工作流已经将业务编排蓝图实例化为可逐节点执行的项目，但节点侧栏目前只提供提示词、执行按钮和原始 JSON，视频工作室仍是独立页面，项目执行者不能在画布中完成“生成、选择、微调、确认、传递”。

本次新增统一的“节点工作台”交互，目标是：

1. 点击画布节点即可打开与模块能力匹配的工作台弹窗。
2. 视频工作室节点在弹窗中复用现有真实视频处理能力。
3. 每个节点都采用“选择输入 → 推荐提示词 → 人工微调 → 执行 → 选择成果 → 确认传递”的统一流程。
4. 每一步输入、输出、状态、模型和来源都直接显示在项目工作流画布中。
5. 保留现有视频工作室、内容工作室及其他独立页面，不修改既有路由和业务数据契约。

## 2. 方案选择

### 方案 A：将完整视频工作室页面嵌入弹窗

实现较快，但页面级组件包含列表、详情抽屉、路由和轮询状态，直接嵌入会造成布局冲突和状态耦合，不采用。

### 方案 B：统一节点工作台 + 模块适配器（采用）

弹窗只实现项目节点需要的流程外壳，各模块通过适配器提供输入表单、生成动作、候选成果和预览。视频能力直接调用现有 `video-studio` API，不复制后端业务逻辑。该方案可复用于后续内容、图片、审核和发布节点。

### 方案 C：为每种模块开发独立节点弹窗

单模块自由度高，但会重复实现输入选择、提示词推荐、错误处理、成果确认和持久化，不采用。

## 3. 核心交互

### 3.1 打开节点工作台

- 单击画布节点后选中节点，并打开“节点工作台”弹窗。
- 右侧检查器保留节点摘要，并提供“打开节点工作台”入口。
- 弹窗顶部显示节点名称、模块、运行状态、实际模型和上次执行时间。
- 弹窗按顺序展示“输入条件、模块能力、提示词微调、候选成果”四个区域。

### 3.2 选择上游输入

- 首节点读取项目创建时的 `initialInput`。
- 非首节点列出所有直接前置节点已经确认的成果。
- 用户选择一条成果后，将其轻量快照和引用保存到当前节点的 `input_snapshot`。
- 未选择必要输入时，执行按钮禁用并展示具体原因。
- 重新选择输入不会删除上游成果；当前节点再次执行时增加 `attempt`。

### 3.3 视频工作室节点

视频节点展示以下真实能力：

- 视频链接或平台分享文本输入。
- 处理策略：视频转录或视频炼金术。
- 转录参数：ASR 模型与语言。
- 炼金术参数：目标平台。
- 真实处理进度、成功反馈和具体错误。

弹窗调用现有 `/api/video-studio/process`。处理结果规范化为候选成果：

- 完整转录稿。
- AI 总结稿（存在时）。
- 改写标题与正文（炼金术结果存在时）。
- 关键观点或标签组合（存在时）。

候选成果保留视频记录 UID、来源 URL、处理策略、模型和真实性信息。用户必须选择一条成果并确认，才将该节点标记为完成并点亮下一节点。

### 3.4 LLM 提示词推荐与人工微调

- 节点工作台调用新增的提示词推荐接口。
- 服务端根据项目名称、工作流节点链、当前模块、目标平台、当前选中输入和历史微调生成 3–5 个模板。
- 每个模板包含标题、适用理由和完整提示词。
- 点击模板只把内容写入“提示词 / 本次微调”，不会自动执行。
- 用户可继续修改提示词，点击执行时才把提示词保存到节点并调用模块适配器。
- 接口返回实际 LLM provider/model；LLM 不可用或返回格式错误时，返回模块专用的本地备用模板，并明确标记 `fallback`。

### 3.5 后续节点

内容、图片和其他后续节点沿用相同外壳：

1. 展示并选择上游成果。
2. 获取与模块相匹配的提示词模板。
3. 人工微调提示词和必要参数。
4. 调用现有模块 API 执行。
5. 将返回值规范化为候选成果。
6. 选择并确认一条成果作为下一节点输入。

尚未接入真实模块适配器的节点保持 `blocked`，弹窗显示未接入原因，不伪造成功结果。

## 4. 画布成果展示

项目节点卡片增加以下信息：

- 输入摘要或上游成果名称。
- 当前选定成果的标题或文本摘要。
- 成果类型和候选数量。
- 执行状态、实际模型、耗时和重试次数。
- 图片成果显示缩略图；视频或外部素材显示来源图标和链接域名。

节点卡片不显示完整长文本。点击节点后在工作台弹窗查看完整内容、来源和全部候选，避免画布失控。

## 5. 服务端设计

### 5.1 节点工作台契约

在项目工作流服务中增加以下能力：

- 读取可供当前节点选择的直接上游成果。
- 保存当前节点选中的输入快照和引用。
- 获取 LLM 推荐提示词。
- 保存模块生成的候选成果。
- 确认选定成果，并将节点推进到 `completed`。

### 5.2 API

新增或扩展以下接口：

- `GET /api/project-workflows/:id/nodes/:nodeId/workbench`
  - 返回当前节点、可选输入、候选成果和模块能力描述。
- `PUT /api/project-workflows/:id/nodes/:nodeId/input`
  - 保存用户选择的输入成果。
- `POST /api/project-workflows/:id/nodes/:nodeId/prompt-recommendations`
  - 返回 3–5 个推荐提示词及实际模型信息。
- `POST /api/project-workflows/:id/nodes/:nodeId/video/generate`
  - 复用视频工作室服务生成并持久化视频候选成果。
- `POST /api/project-workflows/:id/nodes/:nodeId/select-result`
  - 保存选定成果并完成节点，推进到下一节点。

原有 `execute`、`confirm` 和 `execute-continuously` 接口继续兼容。连续执行遇到需要人工选择成果的节点时暂停。

### 5.3 数据保存

优先复用现有字段，不新增重复业务表：

- `input_snapshot`：已选择的输入快照、上游节点 ID 和成果引用。
- `output_snapshot`：候选成果数组和当前选定成果。
- `artifact_refs`：视频记录 UID、内容 ID、图片 ID 等稳定引用。
- `source_refs`：来源 URL、平台、采集时间和真实性类型。
- `prompt`、`provider`、`model`：本次微调及实际 LLM 信息。

候选成果只保存本节点直接结果，不递归复制完整历史链。

## 6. 前端组件边界

- `ProjectWorkflowCanvas.vue`：负责画布选择、打开工作台和刷新工作流。
- `ProjectResultNode.vue`：负责紧凑展示输入与选定成果摘要。
- 新增 `ProjectNodeWorkbench.vue`：统一弹窗、步骤状态、错误反馈和成果选择。
- 新增模块面板或组合函数：视频工作室参数、真实进度和候选结果规范化。
- `client/src/api/index.ts`：增加节点工作台相关 DTO 和 API 调用。

弹窗组件不直接修改工作流父级状态；每次服务端操作成功后返回最新项目工作流，由父级统一刷新。

## 7. 状态与错误处理

- `pending`：等待选择输入或执行。
- `running`：模块正在执行，按钮显示 loading，防止重复提交。
- `waiting_review`：已有候选成果，等待用户选择并确认。
- `completed`：已有选定成果，可作为下游输入。
- `failed`：保留输入、提示词和错误，允许修改后重试。
- `blocked`：模块未接入或缺少必要配置，展示配置路径或缺失原因。

视频长任务关闭弹窗后不取消后端任务；重新打开时通过记录或进度接口恢复状态。任何失败都必须显示服务端具体错误，不使用笼统的“请求失败”覆盖原因。

## 8. 兼容性与范围

- 不修改现有 DOM 路由、业务 API 字段名和独立模块入口。
- 不自动向外部平台发布内容。
- 不在本阶段引入队列、事件总线或新的分布式任务系统。
- 不把未接入模块伪装为成功执行。
- 不删除已有项目工作流、视频记录或生成内容。

## 9. 验收标准

```gherkin
Feature: 项目节点工作台

  Scenario: 在视频节点生成并选择成果
    Given 项目工作流当前节点是视频工作室
    When 用户打开节点工作台并提交有效视频链接
    Then 系统应调用现有视频工作室真实处理服务
    And 应显示处理进度和规范化后的候选成果
    And 用户选择一条成果并确认后节点应变为已完成
    And 下一节点应能选择该成果作为输入

  Scenario: 使用推荐提示词进行人工微调
    Given 当前节点已经选择有效输入
    When 用户请求提示词推荐
    Then 系统应返回三到五个与项目和节点相关的模板
    And 应显示实际使用的 LLM 或备用模板标识
    When 用户点击一个模板
    Then 模板内容应填入提示词微调区
    And 系统不应自动执行节点

  Scenario: 在画布直接查看执行成果
    Given 一个节点已有选定成果
    When 用户返回项目工作流画布
    Then 节点卡片应显示输入摘要、成果摘要、状态和模型信息
    And 刷新页面后这些信息不应丢失

  Scenario: 失败后修改并重试
    Given 节点执行失败
    When 用户重新打开节点工作台
    Then 原输入、提示词和具体错误应继续显示
    When 用户修改参数并重新执行
    Then 系统应增加尝试次数并保存新的结果

  Scenario: 未接入模块不伪造成功
    Given 当前模块没有真实项目节点适配器
    When 用户打开或执行该节点
    Then 系统应显示 blocked 状态和未接入原因
    And 不应生成模拟成功成果
```

## 10. 测试范围

- 服务端单元测试：输入选择校验、提示词解析与 fallback、视频候选规范化、成果确认和节点推进。
- API 回归：新增工作台接口、原有项目工作流接口、视频工作室接口。
- 前端构建与类型检查：节点工作台、画布节点 DTO、错误与 loading 状态。
- 核心交互回归：打开视频节点、生成候选、选择成果、填入模板、人工微调、完成节点、刷新恢复。
- 深浅模式对照：弹窗、成果卡片、节点状态和长文本预览。
