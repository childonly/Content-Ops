# 正式目录同步与深色主题设计

日期：2026-07-30  
正式项目：`E:\000 【AI-项目】\Trae_work\content-ops-hub`

## 目标

将 `E:\Documents\content-ops-hub` 中经逐文件差异核验、确有价值的修复迁移到正式目录，并在不改变页面结构和交互逻辑的前提下，完成可维护的深色主题。

## 工作边界

- 正式目录是唯一主项目；所有构建、测试和服务启动均从正式目录执行。
- 不创建 Git 分支或 Codex worktree；项目初步稳定后再建立 Git 基线。
- 不复制或替换 SQLite 数据库及其 `db-wal`、`db-shm` 文件。
- 不复制日志、浏览器 Profile、依赖目录、构建产物、备份目录或临时应用脚本。
- 临时文件仅允许放在 `logs/codex-temp`。
- 主题改造只修改主题令牌、CSS 和组件样式；不修改 DOM 结构、路由、事件、API、字段名或业务逻辑。
- T02–T04 迁移可保留其已经确认的数据库字段、API 和业务修复；这些变更不属于主题改造。

## 迁移范围

### T01：运行时基线

- 添加 Node.js 22 版本约束和解析脚本。
- 启动脚本必须通过脚本自身位置解析正式项目根目录，不得硬编码 `E:\Documents\content-ops-hub`。
- 启动后验证后端 3100、前端 5180。

### T02：模块运行配置持久化

- 为 `module_settings` 增加 `selected_skill`、`selected_llms`，迁移保持幂等。
- 统一内容工作室模块 ID 为 `content`。
- 后端提供模块运行配置的读取、校验和更新。
- 前端加载、保存并在失败时回滚 Skill/LLM 选择。
- 迁移相应单元测试。
- 不把未接入路由的“自定义 LLM upsert”宣称为已完成；只保留实际接线并可验证的部分。

### T03：发布真实性

- 发布记录保存实际引擎。
- 仅显示当前真实支持的小红书平台和可用发布引擎。
- 非 JSON、`ready` 状态或缺少明确成功证据的发布结果不得判定为成功。
- 默认发布引擎持久化；不可用引擎不能设为默认。
- 发布失败使用失败 HTTP 状态和失败记录，不更新内容为已发布。
- 保留人工确认边界，不自动触发真实发布回归。

### T04：数据真实性

- 仪表盘发布数只统计 `status = 'published'`。
- UI 标签改为“成功发布数”。

### T05：暂不迁移

副本中的 T05 目标源文件与正式目录哈希一致，仅存在未纳入测试目录的 `.pending` 测试，因此后续应在正式目录重新设计、实现和测试。

## 深色主题

### 视觉方向

- 背景采用石墨深灰和冷中性灰，不使用深蓝、紫色或粉色环境光。
- 唯一品牌强调色为蓝色。
- 红、黄、绿仅用于错误、警告、成功等语义状态。
- 移除主按钮、导航激活态和品牌图标的蓝紫渐变。
- 状态点使用实色、边框或低对比背景，不使用霓虹外发光。
- 卡片使用克制的层级面和中性阴影，不使用大面积玻璃光晕。

### 主题令牌

- 补齐页面、表面、浮层、悬浮、输入、边框、文本和禁用态令牌。
- 增加品牌色的亮暗阶及语义状态的柔和背景令牌。
- 补齐 Element Plus 的基础、浅阶、深阶、填充、边框、禁用、遮罩和弹出层变量。
- 浅色主题外观保持现状，只补充缺失的语义令牌。

### 组件适配

- `MainLayout`：导航激活态改为品牌蓝实色；状态点移除外发光。
- `AdminView`：对话气泡改用主题表面和语义边框。
- `ContentStudio`：编辑器、预览、模板卡片、统计及遮罩改用令牌。
- `FlowHome`、`ModuleInfoCard`、`ModuleNode`：浅色硬编码替换为主题令牌；模块业务色仅作为必要的数据识别色，不作为全局强调色。
- `ExternalPage`：加载、错误与文字颜色改用令牌。

## 验证

- 后端单元测试全部通过。
- 后端 TypeScript 构建和前端 Vue TypeScript/Vite 构建通过。
- 正式目录在 Node.js 22 下启动，3100 与 5180 均监听。
- 验证 `/health` 和前端入口。
- 对浅色、深色分别检查仪表盘、内容工作室、发布队列、系统管理和流程图。
- 回归主题切换、导航、弹窗、表格、表单、发布引擎选择和模块 Skill/LLM 选择。
- 不执行真实社媒发布。

## 失败处理

- 迁移或构建失败时保留原运行数据库，不用副本数据库覆盖。
- 服务端口被其他目录进程占用时，先识别进程来源；只停止明确属于旧副本的项目进程。
- 对未验证或相互矛盾的副本变更，优先在正式目录重写并增加测试，而不是直接复制。
