# 内容工作室节点工作流实施计划

## 第一阶段：稳定性基线

- 保持趋势删除事务：先解除 hashtags、contents、pipeline_runs 的 trend_id，再删除 trends。
- 登录面板显示 Python、Skill 路径、浏览器和失败原因；将“未登录”和“命令执行失败”区分展示。
- 发布结果只有在引擎返回真实笔记 URL 时才标记为已发布。

## 第二阶段：动作能力目录

新增前端只读能力目录（不改现有接口）：每个动作声明前置条件、输入字段、输出字段、目标路由和可用引擎。右键菜单根据该目录过滤动作。

建议动作 ID：`research.hashtags`、`content.generate`、`content.edit`、`media.generate`、`content.review`、`publish.queue`、`publish.now`、`analytics.track`。

## 第三阶段：工作流壳层

- 在 Content Studio 增加工作流画布/流程条，节点引用已有 trend/content/pipeline 数据。
- 节点点击打开检查器；右键显示推荐下一步；添加节点时复制上游引用并使用默认配置。
- 执行动作仍调用现有 API，先实现单节点执行和状态回填，再实现连续执行。

## 第四阶段：持久化与恢复

优先复用 `business_flows` 的 nodes/edges。需要断点续跑时再增加兼容字段或独立运行表，记录 node status、startedAt、completedAt、error 和 outputRef。迁移只允许新增字段/表，不删除既有数据。

## 第五阶段：简化旧界面

- 页面顶部只保留当前阶段主按钮。
- 将重复的“生成/保存/提交/发布”合并为阶段菜单。
- 高级配置统一放入右侧检查器，并提供“推荐配置”和“最近使用”。
- 旧路由和旧按钮保留为兼容入口，待节点工作流稳定后再逐步降级为次要入口。

## 回归清单

- 趋势单删、批量删及存在标签/内容/流水线引用的情况。
- 未登录、扫码登录、登录状态刷新和发布失败重试。
- 趋势到草稿、草稿到配图、审核到发布的主流程。
- 旧页面按钮、路由、API 字段和浅色/深色主题。
